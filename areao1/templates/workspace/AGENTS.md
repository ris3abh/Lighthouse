# Agent guide for this Area O1 workspace

This directory is a private immigration-case workspace managed by
[Area O1](https://github.com/ris3abh/areao1) (`areao1`). It is the single source of
truth for the case. Read this before changing anything.

## Rules

1. **Human-in-the-loop for evidence.** Never add to `data/exhibits.json` or `evidence/` directly. Propose
   evidence by adding a candidate to `data/inbox.json` (status `pending`); the user accepts it in the Inbox.
   Approval records a decision; it does not certify truth or legal sufficiency.
2. **Draft only from approved claims.** Facts live in `memory/claims.jsonl`, each quoting its source verbatim
   (`excerpt` at `excerpt_start..excerpt_end` in the snapshot under `memory/sources/`). Only claims whose latest
   decision in `memory/decisions.jsonl` is `approved`, and that nothing SUPERSEDES, may be cited. Where proof is
   missing, say what is unknown instead of filling the gap.
3. **Invitation is not completion.** Respect `stage`: an invitation to judge is `invited`, not `completed`;
   a preprint is not `published`. Only completed / published / granted stages count toward a criterion.
4. **Self-reported is not evidence.** Observations with tier `self_reported` (e.g. imported chat history)
   can update trackers but never count toward a criterion or support a petition-facing statement.
5. **Memory is append-only.** Never edit or delete lines in `memory/*.jsonl`; a newer claim supersedes an older one.
6. **Validate every write.** Each `data/*.json` file has a JSON Schema in `.areao1/schemas/`. Run
   `areao1 validate` after editing.
7. **Never write secrets** (tokens, passwords, salary figures you weren't asked to record) into any file.
   Tokens live in the OS keychain.
8. **Don't edit generated files.** `DASHBOARD.md` and `data/criteria.json` are regenerated by
   `areao1 run dashboard`.
9. **Not legal advice.** Any judgment you write ("how a reviewer would see this") is an opinion and must be
   labeled as one.

## Layout

| Path | What |
|---|---|
| `areao1.yaml` | profile (`o1a` / `eb1a`), schedules, criterion overrides. No secrets. |
| `data/person.json` | who the case is for |
| `data/sources.json` | connected sources and tracked items |
| `data/inbox.json` | candidates awaiting the user's decision |
| `data/exhibits.json` | accepted evidence, each mapped to a criterion and a file in `evidence/` |
| `data/criteria.json` | computed scoreboard (generated) |
| `data/metrics.csv` | `date,source,item,metric,value` snapshots |
| `data/pipeline.json`, `letters.json`, `deadlines.json`, `opportunities.json` | in-flight work |
| `evidence/<criterion>/` | exhibit files named `<crit>_<yyyy-mm-dd>_<slug>.<ext>` |
| `memory/` | append-only evidence graph: observations, claims (with verbatim excerpts), edges, decisions; raw snapshots in `memory/sources/` |
| `drafts/letters/` | recommendation letter drafts |

## Useful commands

```sh
areao1 up                      # dashboard at http://127.0.0.1:7777
areao1 import <url>            # add a GitHub / Hugging Face source
areao1 run sync                # refresh sources, new candidates -> Inbox
areao1 run metrics-snapshot    # append today's metrics to data/metrics.csv
areao1 run dashboard           # re-score and regenerate DASHBOARD.md
areao1 validate                # check every file against its schema
```
